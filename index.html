Entity Resolution · NLP · Semantic Search
Product Matching Pipeline

The question that hooked me: two listings can share 95% of their words and still be different products. I wanted to know exactly where similarity should stop counting.

Solves the core e-commerce problem: millions of sellers list the same product with different titles, abbreviations, and formats. The system identifies which listings refer to the same real-world product.

The problem with vanilla transformers: "Sony XM5 Headphones" vs "Sony XM4 Headphones" scores 0.97 cosine similarity — nearly identical, but they're different products. A single digit difference gets drowned out by surrounding shared words.

Two-stage solution: Sentence Transformer (all-MiniLM-L6-v2) for semantic similarity, followed by an Attribute Guard that detects model code, storage, and size conflicts using regex. Conflicts multiply the score by a penalty (0.40–0.50), collapsing the false match from 0.97 → 0.49.
78% → 92%+ accuracy 40-pair evaluation set

Text Classification · DistilBERT · Multi-task Learning
Hierarchical Taxonomy Classifier

I didn't want three separate models drifting apart from each other — I wanted to know if one shared encoder could actually learn all three levels at once.

Automates product categorization for e-commerce listings. Given any product title, predicts the full 3-level category path (e.g., Electronics → Audio → Headphones) in under 100ms on CPU.

Architecture: Fine-tuned DistilBERT with 3 simultaneous classification heads (5 / 12 / 18 classes) trained end-to-end. One shared encoder learns features for broad and fine-grained taxonomy simultaneously — the combined loss (L1 + L2 + L3) backpropagates through all three heads in a single step.

Why DistilBERT over BERT? 40% smaller, 60% faster, retains 97% performance — runs in ~80ms vs ~200ms per title on CPU, critical for listing ingestion pipelines.
100% L1 accuracy 81% L3 accuracy 73% on unseen product types

Named Entity Recognition · BIO Tagging · Token Classification
Product Attribute Extractor (NER)

"iPhone" splits into ["i", "##phone"] under the hood — I wanted to understand exactly how that subword split should change where labels get scored.

Turns raw, unstructured product titles into structured, queryable attributes. Feeds directly into the Entity Resolution pipeline — the Attribute Guard uses these extracted values for conflict detection.

9 entity types: BRAND, MODEL, COLOR, STORAGE, SIZE, MATERIAL, NETWORK, GENERATION, COUNT. Handles multi-word entities like "Le Creuset", "Deep Purple", "Cast Iron" using BIO tagging.

Subword alignment: Labels are predicted only for the first subword of each word; continuation subwords are masked with -100 in the loss — the industry standard for BERT-based NER. Evaluated with seqeval at the span level, not token level.
F1=1.00 on BRAND F1=0.86 on STORAGE Overall F1=0.61 (9 types)

Computer Vision · EfficientNet · Explainable AI
Product Image Quality Scorer

A single quality score felt like a black box — I wanted the system to be able to tell a seller exactly what's wrong, not just how bad it is.

Scores product photos on a 1–5 scale and generates actionable seller feedback — not just a number, but exactly what is wrong and how to fix it. Built for eBay-style listing quality enforcement.

Two-stage architecture: EfficientNet-B0 (4.3M params, ImageNet pretrained, MSE regression head) combined with 7 classical CV signals — Laplacian sharpness, brightness penalty, contrast, colorfulness, edge density, resolution, noise. Final score = 0.65 × CV + 0.35 × DL.

Why combine both? CV signals are fast, explainable, and reliable ("Laplacian variance: 0.03 — your image is blurry"). EfficientNet captures holistic quality that's hard to measure explicitly. Diagnosis always comes from CV signals, never the neural network, so advice stays grounded.
7 CV signals Correct ranking on all test images Actionable feedback per image

Computer Vision · Anomaly Detection · Manufacturing
Manufacturing Defect Detection System

Labeled defect data is expensive and rare — I got curious whether a model could learn to flag "wrong" having only ever seen "right."

A real-time quality control pipeline for electronics manufacturing — flags anomalous products during inspection before they reach downstream assembly or customers.

Architecture: Convolutional autoencoder trained exclusively on defect-free images. At inference time, high reconstruction error flags an anomaly — the model learns what "normal" looks like and rejects everything that deviates. Optionally extended with a supervised ResNet-18 classifier for defect categorization when labels are available.

Why unsupervised? Training only on good images means the system deploys with zero defect labels — it learns the distribution of normal products and flags anything outside it.
MVTec AD dataset Up to 40% inspection labour reduction Real-time Streamlit dashboard
Industry benchmarks: early anomaly detection systems of this type reduce manual inspection labour by up to 40% and catch defect rates human inspectors miss at high throughput.

LLM Observability · Full-stack · Production ML
AI Guardian

Nobody assigned this. The question that hooked me wasn't "does it work" but "how would I even know if it silently stopped working."

The hardest part of deploying a GenAI system is not building it — it's knowing whether it still works correctly three weeks later. AI Guardian solves this with event-driven LLM monitoring in production.

How it works: Python SDK (@track_llm_call decorator) captures latency, token usage, cost, quality scores, and hallucination risk for every LLM call without modifying application code. Threshold-based alerting fires before issues escalate — it's already caught 3 real behavioral drift events before a single user noticed. All metrics flow into a PostgreSQL backend and surface in a React dashboard with live WebSocket updates.

Works with any LLM provider: OpenAI, Anthropic, Google. Designed to be dropped into an existing LLM application with a single decorator.
Real-time monitoring 3 drift events caught pre-launch Zero application code changes

Statistical Modeling · Fairness Analysis
Credit Risk Classification

The most accurate model wasn't the fairest one — I wanted to know exactly how much accuracy that fairness gap was actually costing, not just that it existed.

Applied ML model development to a real-world financial-services problem: predicting credit risk while explicitly measuring whether the model treats demographic groups equally.

Approach: Built and compared Logistic Regression, SVM, and Random Forest classifiers on the German Credit Dataset with stratified 80/20 split and 5-fold cross-validation with grid search, evaluated across accuracy, F1, and ROC-AUC.

The real finding: Ran subgroup fairness analysis computing false-positive/false-negative rates across demographic groups — Random Forest had the highest AUC but the widest fairness gap, a direct accuracy-vs-fairness trade-off most model comparisons skip entirely.

Deep Learning · CNN · Low-Resource NLP
Arabic Handwriting Recognition

Transfer learning is the easy button — I wanted to know what a CNN designed specifically for Arabic script could do without leaning on it at all.

CNN trained from scratch to classify all 28 Arabic handwritten characters across 13,440 labeled images. Goal: verify that a well-designed custom CNN can compete with transfer learning on a low-resource task.

Design decisions: Data augmentation (rotation, shear, zoom) to address class imbalance. Dropout regularization to prevent overfitting. Confusion matrix analysis identified the character pairs with the highest confusion rates, informing post-training threshold adjustment.

Why train from scratch? Stroke patterns and character anatomy in Arabic script don't map well to ImageNet features. A CNN designed specifically for the structure of Arabic script outperforms naive transfer.
92.4% test accuracy 28 character classes 13,440 labeled images
